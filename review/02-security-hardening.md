# 02. Усиление безопасности и защита от утечек (P1)

Выполнять после 01-critical-security.md (задачи ссылаются на введённые там MEK-функции).

## H1. Держать в памяти CryptoKey вместо строки мастер-пароля

**Где:** `src/core/state.js` (`state.masterPassword`), `src/sidepanel/index.js` (повсеместно).

**Проблема:** plaintext-пароль живёт в JS-строке всё время сессии; строки неизменяемы и остаются в куче до GC, попадают в краш-дампы/снапшоты памяти.

**Что сделать:** после C1/C2 единственный долгоживущий секрет — MEK как non-extractable `CryptoKey`. `state.masterPassword` удалить из состояния; все сравнения «введите текущий пароль» выполнять через попытку `unwrapMekWithPassword` на актуальном конверте (это заодно устраняет сравнение `oldPwd !== state.masterPassword` в `src/sidepanel/index.js:4113`, которое не констант-тайм и завязано на копию пароля). Временные `Uint8Array` с ключами — `fill(0)` сразу после импорта.

**Критерии приёмки:** `grep -n "masterPassword" src/ -r` не находит долговременного хранения строки пароля в state; все операции работают.

## H2. Автолок по бездействию и при закрытии панели

**Проблема:** сейчас нет авто-блокировки: открытая панель с расшифрованным хранилищем остаётся доступной неограниченно; `sessionExpiresAt` проверяется только при старте.

**Что сделать:**
1. В sidepanel: таймер бездействия (настройка «Автоблокировка»: 1/5/15/30 мин, по умолчанию 15; сбрасывается по `pointerdown`/`keydown`), по истечении — `lockVault()`.
2. Периодическая проверка истечения сессии: `setInterval` раз в 30 с сравнивает `Date.now()` с `sessionExpiresAt` → `lockVault()`.
3. Опция «Блокировать при сворачивании панели» (по `visibilitychange: hidden` + задержка 60 с).
4. В background: `chrome.idle.onStateChanged` (permission `idle`) — при `locked` (блокировка ОС) очищать `chrome.storage.session` ключ сессии.

**Критерии приёмки:** панель, оставленная без действий на настроенный интервал, показывает экран ввода пароля.

## H3. Надёжная автоочистка буфера обмена

**Где:** `src/core/state.js:copyToClipboard` — `setTimeout` в документе sidepanel; при закрытии панели таймер умирает, пароль остаётся в буфере навсегда. Также `navigator.clipboard.readText()` требует разрешения чтения и может кидать.

**Что сделать:**
1. Очистку перенести в background: после копирования sidepanel шлёт `{type:'SCHEDULE_CLIPBOARD_CLEAR', seconds}`; background ставит `chrome.alarms.create('sp-clear-clipboard', { delayInMinutes: seconds/60 })` (permission `alarms`).
2. По срабатыванию alarm — очистка через offscreen document (permission `offscreen`, API `chrome.offscreen`): offscreen-страница пишет в clipboard пустую строку/пробел через `navigator.clipboard.writeText(' ')`. Сравнение «а наш ли текст в буфере» убрать (чтение буфера = лишняя привилегия); очищать безусловно, это честнее.
3. В UI показывать обратный отсчёт очистки на карточке/тосте (см. U7).

**Критерии приёмки:** скопировать пароль → закрыть панель → через настроенный интервал буфер очищен.

## H4. AAD-привязка и целостность конверта

**Где:** `src/core/crypto.js`.

**Что сделать:** при шифровании payload и ключевых слотов передавать `additionalData` в AES-GCM: `enc.encode('simplepass|v2|' + slotName)` (например `payload`, `mek-pwd`, `mek-rec`). Это исключает подмену слотов местами и даунгрейд-атаки на структуру конверта. Версию конверта поднять до 3, сохранив чтение v1/v2 (без AAD) для миграции; при первом успешном открытии пересохранять как v3.

**Критерии приёмки:** тест: подмена `keyByRecovery`↔`keyByPassword` в v3-конверте приводит к ошибке расшифровки.

## H5. Генератор recovery-фразы: честная маркировка и запас прочности

**Где:** `src/core/crypto.js` — `RECOVERY_WORDLIST` (256 слов) и комментарий «BIP-39 compatible».

**Проблема:** фраза не BIP-39 (нет контрольной суммы, словарь 256 слов, а не 2048); 12 слов × 8 бит = 96 бит — приемлемо, но маркировка вводит в заблуждение, и нет защиты от опечаток.

**Что сделать:** (а) убрать слова «BIP-39» из кода/README; (б) при вводе фразы проверять каждое слово по словарю и подсвечивать нераспознанные с подсказкой ближайшего слова (расстояние Левенштейна ≤2); (в) опционально увеличить словарь до 1024 слов (10 бит/слово → 120 бит) — только вместе с версией конверта, чтобы старые фразы продолжали работать (нормализация и словарь проверки должны покрывать оба словаря).

## H6. Политика мастер-пароля и индикатор силы

**Где:** `src/core/crypto.js:validateMasterPassword` (требования: >8 символов + 1 спецсимвол).

**Что сделать:** минимальная длина 10; убрать жёсткое требование спецсимвола для длинных (≥16) парольных фраз; при создании/смене показывать индикатор силы (использовать `evaluatePasswordStrength`, а лучше подключить `zxcvbn-ts` — см. F7); предупреждать (не блокировать) при силе «Weak». Все сообщения — через `t()`.

## H7. Подтверждение и защита экспорта в открытом виде

**Где:** `src/sidepanel/index.js:4220-4262` (CSV/Bitwarden JSON), `downloadItemAsCsv` (1287).

**Что сделать:** перед любым plaintext-экспортом: (а) модал с предупреждением «файл будет содержать пароли в открытом виде»; (б) повторный ввод мастер-пароля (проверка через `unwrapMekWithPassword`); (в) добавить вариант «Зашифрованный бэкап (.spbackup)» — JSON-конверт теми же `encryptVault`-функциями с паролем экспорта, и соответствующий импорт. Экспорт по умолчанию — зашифрованный.

## H8. Защита от brute-force конверта: метаданные и padding

**Приоритет низкий.** В конверте нет ничего лишнего — хорошо. Дополнительно: сериализуемый payload дополнять случайным полем `_pad` (16–64 байт base64) для сокрытия точного размера хранилища от наблюдателя файловой системы. Опционально.

## H9. Безопасность сообщений между контекстами

**Где:** `src/background.js` — `onMessage` обрабатывает `AUTOFILL_LOGIN`/`GET_ACTIVE_TAB_INFO` от любого отправителя внутри расширения; `src/content/content.js` — отвечает на `GET_PAGE_FAVICON` и `DO_AUTOFILL`.

**Что сделать:** в background проверять `sender.id === chrome.runtime.id` и что `sender.url` начинается с `chrome-extension://<id>/sidepanel.html` для `AUTOFILL_LOGIN`; в content script обрабатывать сообщения только с `sender.id === chrome.runtime.id` и без `sender.tab` (т.е. от расширения, не от других вкладок). Это дёшево и закрывает будущие регрессии.

## H10. Убрать секреты из value-атрибутов DOM

**Где:** `src/sidepanel/index.js:1904` — пароль записи подставляется в `value="${escapeHtml(item.password)}"` внутри `innerHTML`-шаблона формы.

**Проблема:** пароль попадает в сериализованный HTML (доступен расширениям с DOM-доступом это неизбежно, но также остаётся в строках шаблонов и потенциальных логах/снапшотах DOM).

**Что сделать:** рендерить input пустым и выставлять значение программно после вставки шаблона: `document.getElementById('sp-item-password').value = item.password`. То же для полей с username допустимо оставить. Добавить `autocomplete="new-password"` и `spellcheck="false"` на поля секретов, `inputmode="text"`.
