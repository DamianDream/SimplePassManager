## Глобальные правила для агентов-исполнителей

1. **Обратная совместимость хранилища обязательна.** У пользователей уже есть зашифрованные конверты v1 и v2 в `chrome.storage.local`. Любое изменение формата конверта выполняется только с кодом миграции и повышением поля `version`. Старые конверты должны продолжать расшифровываться.
2. **Не менять криптопримитивы без явного указания.** AES-256-GCM + PBKDF2-SHA256/600k — базовая схема, менять только по задачам из 02-security-hardening.md.
3. **После каждой задачи:** `npm run build` должен проходить без ошибок; `node tests/test-core.mjs` — зелёный; новые модули покрывать тестами в `tests/`.
4. **Каждая задача = отдельный атомарный коммит** с префиксом `fix(security):`, `fix:`, `feat:`, `refactor(ui):` и ссылкой на ID задачи (например `C1`, `H3`, `B5`).
5. **Все пользовательские строки — только через `t()`** (`src/core/i18n.js` + `src/locales/translations.json`). Хардкод русских строк запрещён (см. B4).
6. **Никогда не логировать** в `console.*` пароли, мастер-пароль, recovery-фразу, расшифрованные данные, содержимое буфера обмена.
7. Файл `src/sidepanel/index.js` (4451 строка) постепенно распиливается на модули (см. 06-ui-ux.md, задача U1); при правках не увеличивать его размер новыми большими блоками — новый код выносить в `src/sidepanel/views/` и `src/sidepanel/handlers/`.

## Сводка состояния проекта

**Сильные стороны:** корректная базовая криптография (AES-256-GCM, PBKDF2 600k итераций, случайные salt/IV на каждую операцию, dual-key конверт v2 с MEK), systematic `escapeHtml()` в шаблонах, RFC-4180 CSV-парсер, наличие unit-тестов ядра, MV3.

**Критические проблемы (детали в 01-critical-security.md):**
- C1. Мастер-пароль сохраняется на диск в base64 (`chrome.storage.local`) на срок до 30 дней — полная компрометация модели шифрования.
- C2. Каждое сохранение записи молча деградирует конверт v2→v1 и уничтожает ключ восстановления (12 слов перестают работать).
- C3. Автозаполнение не проверяет соответствие домена записи активной вкладке; доменный матчинг уязвим к фишингу.
- C4. Native messaging host: невалидный wildcard в `allowed_origins`, path traversal в `handle_get`.
- C5. Домены всех записей пользователя утекают в Google/DuckDuckGo через favicon-API.
- C6. Счётчик неудачных попыток входа хранится в открытом виде и обходится; при этом навсегда блокирует честного пользователя.
